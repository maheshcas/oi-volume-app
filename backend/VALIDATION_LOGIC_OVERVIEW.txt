Current Backend Corrections

Target Engine / Breakout Probability
backend/app/engines/target_engine.py
backend/app/engines/breakout_probability_engine.py
- Target distance is now anchored to the live S/R band, not just expectedMove / adjustedMove.
- Core calculation:
  - band_width = resistance - support
  - base_move = band_width * (1 + oi_power) * vol_factor
- Target scaling:
  - target_1 uses 0.8x base_move
  - target_2 uses 1.5x base_move
  - extended_target uses 2.5x base_move
- Sanity clamp:
  - target distance is capped at 3x band from the broken level
- Debug trace added:
  - TargetEngine[expectedMove=... adjustedMove=... band=... baseMove=...]
- Breakout probability now includes final proximity weighting:
  - closer to resistance -> upside probability boosted
  - closer to support -> downside probability boosted

SR Engine Hysteresis
backend/app/engines/sr_engine.py
- Immediate support/resistance selection now includes a hold-previous hysteresis layer.
- A new immediate level only replaces the previous active level when it is meaningfully stronger:
  - roughly 18 percent score improvement
  - or roughly 15 percent OI improvement
- Purpose:
  - stop 23,800 <-> 24,000 resistance ping-pong
  - stabilize detected regime input
  - allow candidate_regime_count to accumulate instead of resetting on every minor SR flip

Session Phase Timestamp Fix
backend/app/services/background_updater.py
- _parse_timestamp_utc() now treats NSE-style timestamps:
  - %d-%b-%Y %H:%M:%S
  - %d-%b-%Y %H:%M
  as IST first, then converts to UTC.
- This prevents session_phase from being stuck on Transition because of naive timestamp timezone drift.
- Session phase should now be able to advance into:
  - Structure Formation
  - Compression Phase
  - Position Build Phase
  - Expansion Window

Stability Logger Lock Fix
backend/app/services/stability_logger.py
- Process lock file now writes the real PID in fixed-width hex:
  - f\"{os.getpid():08x}\"
- On release the lock file resets to:
  - 00000000
- Purpose:
  - remove PID=0 ambiguity
  - make logger-owner tracing reliable
  - reduce false duplicate-start ambiguity during session restarts

Regime Hysteresis / Zone Mapping
backend/app/services/background_updater.py
- Committed regime used by validation/logging is now owned by the final decision-state layer, not only the coarse pre-decision regime engine.
- Explicit hysteresis state:
  - current_committed_regime
  - candidate_regime
  - candidate_regime_count
- Effective regime switch requires 3 consecutive detection cycles before adopting the candidate for normal structural shifts.
- Decision-state mapping used for the accumulator:
  - Range Play / Standby -> Range Day
  - Balanced / Wait / Balanced Structure -> Balanced Structure
  - Transition Phase -> Transition
  - trend / aggressive trend / cautious trend -> Trend Day
  - breakdown states -> Breakdown Day
- background_updater persists:
  - committed_regime
  - detected_regime
  - candidate_regime
  - candidate_regime_count
  - regime_zone
- Validation sequence to expect during a normal regime promotion:
  - cycle N+0: candidate_regime != "" and candidate_regime_count = 1 while committed_regime is unchanged
  - cycle N+1: same candidate_regime and count = 2
  - cycle N+2: same candidate_regime and count = 3
  - cycle N+3: committed_regime flips, candidate_regime clears, count resets to 0
- Failure signatures:
  - count stuck at 1 -> accumulator reset/persistence bug
  - candidate changes mid-ladder -> detected regime unstable inside the 3-cycle window
  - committed flips before count reaches 3 -> bypass path exists
  - candidate clears without committed flip -> wrong state key written
- Zone mapping used for action stability:
  - WAIT_ZONE
    - Standby
    - Range Play
    - Range Day
  - WATCH_ZONE
    - Balanced/Wait
    - Balanced Structure
  - TREND_ZONE
    - Transition Phase
    - Trend Day
    - Breakdown Day
- Trade action should only materially change when zone changes, not on every candidate regime flip.

Immediate Breach Regime Override
backend/app/services/background_updater.py
- Confirmed material breaches bypass the slow 3-cycle accumulator.
- Override rules:
  - confirmed resistance breach -> Trend Day
  - confirmed support breach -> Breakdown Day
  - confirmed breach + absorption_detected -> Trap Day
- When the override fires:
  - committed_regime is promoted immediately
  - detected_regime is set to the override regime
  - candidate_regime is cleared
  - candidate_regime_count resets to 0
- Validation note:
  - a confirmed material breach is already the confirmation event; no additional hysteresis should delay regime promotion

Momentum / DPS / Readiness
In background_updater.py
- Intraday displacement momentum:
  - affects directional force lightly
- Directional Pressure Score (DPS):
  - additive only
  - returns:
    - directional_pressure_score
    - dps_adjusted
    - pressure_state
    - trade_action
    - pressure_explanation
- Trade readiness:
  - based on:
    - clarity
    - alignment magnitude
    - trap penalty
    - execution risk
  - trap deduction skipped when breakout is suppressed or breakout_candidate is true
  - breakout probability is added lightly into readiness
  - returns:
    - trade_readiness
    - readiness_state
- Backend readiness reconciliation gate:
  - Aggressive Trend -> readiness floor 55
  - Cautious Trend -> readiness floor 40
  - Standby -> readiness cap 38
  - BREAKOUT WATCH / BREAKDOWN WATCH -> readiness floor 55
- Readiness hysteresis:
  - uses persisted readiness_active from previous cycle
  - enters ready state at >= 57
  - exits ready state below < 53
  - values between 53 and 57 keep the prior readiness state
  - if watch action is proposed while readiness_active is false, trade_action is forced back to WAIT
  - absorption win forces readiness_active = false

Support Absorption Detector
- Implemented in:
  - app/services/background_updater.py
- Conditions:
  - spot < absorption_reference_level - (strike_gap * 0.4)
  - PE OI change near absorption_reference_level > 10
  - volume_expansion_score > 0.6
  - breakout_strength < 0.35
  - trap_probability > 55
- Support-shift stabilization:
  - tracks previous_support, current_support, absorption_reference_level, support_shift_cycle
  - when support shifts, absorption_reference_level locks to previous_support for 2 cycles
  - after 2 cycles, it switches to current_support only if price is accepted below previous_support and the new support is active
- Output:
  - absorption_detected
  - level
  - message
- Expected interpretation:
  - support is absorbing the breakdown
  - breakdown is likely fake unless follow-through improves
- Conflict resolution:
  - if absorption_detected and material_breach_confirmed both fire:
    - support_abandonment:
      - material breach wins always
    - bearish_positioning:
      - material breach wins when trap_probability <= 70
      - absorption wins only when trap_probability > 70
    - no confirmation_type:
      - absorption wins
- when absorption wins:
  - projection stays Support Broken - Monitoring
  - trade_action remains WAIT
  - readiness is capped at 45
  - readiness_state becomes Absorption Active
  - watch-mode floor is not applied
