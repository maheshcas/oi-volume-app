OptionLens Backend Validation Logic Overview

Maintenance rule
- Update this file whenever backend logic changes affect signal computation, state persistence, API contracts, logger schema, or validation behavior.

Current Backend Runtime State
- Local runtime logging is currently disabled:
  - `OPTIONLENS_ENABLE_CYCLE_LOG=false`
  - `OPTIONLENS_ENABLE_EVENT_LOG=false`
  - `OPTIONLENS_ENABLE_STABILITY_LOGGER=false`
- If a validation session requires cycle, event, or stability evidence, re-enable the relevant logger before collecting logs.

Core Validation Priorities

1. SR stability
- Support / resistance must not ping-pong on small OI rank noise.
- Cold-start / restart paths must not bypass the 25-point structural buffer.
- Validation targets:
  - no downward support move while spot is still above old support - 25
  - no upward resistance move while spot is still below old resistance + 25

2. Regime stability
- Range-family noise must not promote unstable committed regimes.
- `Balanced / Wait`, `Balanced Structure`, and `Standby` are detected-only regimes and must not become the committed regime anchor.
- Range-family committed regimes should stabilize around:
  - `Range Play`

3. Readiness stability
- Active readiness contract is V2.
- Readiness should no longer collapse on one-cycle range-edge or transition flaps.
- Validation target:
  - large sawtooth moves should be materially reduced
  - readiness should reflect structure quality, execution quality, and blocker context rather than label flicker

4. Previous-level persistence
- `previous_support` and `previous_resistance` must persist into:
  - `market_state`
  - persisted `_state`
  - stability snapshots when logger is enabled
- Validation target:
  - frontend previous-level markers should remain available after session open and normal state transitions

5. Symbol coverage
- NSE symbols and SENSEX must all flow through the same v2 summary contract safely.
- Validation target:
  - `/api/v2/intelligence/summary?symbol=SENSEX` returns non-null support / resistance / bias / trap_risk / session_phase

Trap / Regime / Readiness

Trap stack
backend/app/engines/trap_engine.py
- Trap remains a layered score built from:
  - structural validity failure
  - wick / hold failure
  - continuation failure
  - volatility
  - absorption
- Additional trap validation fixes:
  - no-breakout validity floor prevents artificial baseline inflation in quiet sessions
  - rejection wick score is direction-aware (upside uses upper wick, downside uses lower wick)
  - `trap_direction` assignment is resolved before fallback type labeling
  - smoothing now uses previous smoothed value (`trap_smoothed_prev`) instead of raw previous
- Trap stabilizer is active in `background_updater.py`:
  - smoothing
  - hysteresis deadband
  - stable-mid band lock
- Validation/debug fields when logging is enabled:
  - `trap_state`
  - `trap_hysteresis_applied`
  - `trap_smoothed_prev`
  - `trap_trend_adjustment_applied`

Range lock / no-edge stabilizer
backend/app/services/background_updater.py
- Range lock and no-edge shaping are active before final regime stabilization.
- Validation/debug fields:
  - `range_locked`
  - `no_edge`
  - `raw_candidate_regime`
  - `candidate_regime_after_range_lock`
  - `stabilized_regime_family`

Session / SPC Reset

SPC session reset
backend/app/services/background_updater.py
- SPC reset is wall-clock gated by IST trading day, not stale feed timestamps.
- Trigger condition:
  - Monday-Friday
  - IST time >= 09:00
- Key persisted fields:
  - `session_date`
  - `session_phase_session_key`
- Validation note:
  - active processed contracts should roll to the current IST key
  - inactive snapshot files may retain older keys until processed again
- Internal helper `_session_phase_session_key()` takes no arguments; it reads wall-clock IST directly.
  - The `timestamp` parameter that previously existed was never used and has been removed.

Session phase persistence
backend/app/services/background_updater.py
backend/app/engines/session_phase_engine.py
- Session phase persists in `_state` and does not move backward within the same session.
- Validation target:
  - phase should not regress across restart or feed gap within the same trading day

API Security / Input Validation

Query parameter validation
backend/app/routers/option_chain.py
- All GET endpoints enforce an allowlist on `symbol`, `instrument_type`, and `expiry`.
- `symbol` allowlist is built from the `OPTIONLENS_SYMBOLS` env var at startup plus `SENSEX`.
  - Default allowed symbols: `NIFTY`, `BANKNIFTY`, `FINNIFTY`, `SENSEX`
  - Adding a symbol to `OPTIONLENS_SYMBOLS` automatically covers both the background updater and the router.
- `instrument_type` allowlist: `INDICES`, `FUTURES`, `EQUITIES`
  - Frontend sends `Indices`; validated as uppercase `INDICES` (allowed).
  - Validated value is normalized to uppercase before use.
- `expiry` format: `^[A-Za-z0-9\-]+$` (covers NSE format `27-Jun-2024`).
- Invalid values return HTTP 400 before cache lookup, preventing cache-key probing.
- Dead compatibility parameters (`use_sample`, `target_mode`, `confidence_score`) have been
  removed from all endpoint signatures.

Cache key canonical implementation
backend/app/core/cache.py
- `make_cache_key(symbol, instrument_type, expiry)` is the single source of truth.
- Both `background_updater.py` and `option_chain.py` import and alias it as `_cache_key`.
- `stability_logger.py` also uses `make_cache_key`; its former duplicate static method is removed.
- Key format: `{INSTRUMENT_TYPE_UPPER}::{SYMBOL_UPPER}::{expiry or 'AUTO'}`
- Validation implication: all three files always produce identical keys for the same inputs.

Authentication / Middleware

Supabase JWT verification
backend/app/auth.py
- `verify_supabase_jwt` is now an `async` function.
- JWKS fetching uses `httpx.AsyncClient` (non-blocking); the previous `requests.get` call
  blocked the asyncio event loop on every JWKS cache miss.
- JWKS cache TTL remains 1 hour; cache miss is a rare event in steady-state operation.
- `get_current_user` dependency (`app/dependencies.py`) is now `async def` to match.
- `SupabaseAuthMiddleware.dispatch` correctly `await`s `verify_supabase_jwt`.
- Validation implication: authenticated endpoints no longer stall other in-flight requests
  during JWKS refresh.

CORS configuration
backend/app/main.py
- `allow_origins` is driven by the `ALLOWED_ORIGINS` environment variable.
  - Default (development): `http://localhost:5173,http://localhost:3000`
  - Production: set `ALLOWED_ORIGINS` to the deployed frontend URL
    (e.g. `https://your-app.netlify.app`) in the Render environment variables.
- Wildcard `"*"` is never used together with `allow_credentials=True`; doing so is
  rejected by browsers and the CORS spec.
- Validation implication: credentialed cross-origin requests work correctly only when
  `ALLOWED_ORIGINS` explicitly lists the frontend origin.

Application lifecycle
backend/app/main.py
- Startup and shutdown are managed via the `lifespan` async context manager pattern.
- The deprecated `@app.on_event("startup")` / `@app.on_event("shutdown")` decorators
  have been removed.
- Background updater and stability logger tasks are created and cancelled inside `lifespan`.
- Shutdown log messages fire only when the respective tasks were actually started.

Single-worker constraint
backend/app/services/background_updater.py
- All module-level state dicts (`_atr_history`, `_calibrated_weights`, etc.) are mutated
  exclusively by the asyncio background loop.
- The application must run as a single Uvicorn worker (`--workers 1`).
- Running multiple workers silently forks in-memory state, causing history divergence.
- Validated deployment command: `python -m uvicorn app.main:app --host 0.0.0.0 --port 10000`

Exception logging
backend/app/services/background_updater.py
- I/O helper failures (state snapshot load/persist, cycle log, event log, event stream)
  now log at `WARNING` level instead of `DEBUG`.
- Validation implication: disk or permission errors that were previously invisible in
  production logs will now appear as warnings.
