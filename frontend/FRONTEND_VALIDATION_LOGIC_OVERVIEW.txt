Trap card
frontend/src/components/TrapCard.tsx
- Trap card supports:
  - trap_direction
  - trap_affected_level
  - direction-aware suggested action
- Direction pill semantics:
  - downside = Resistance rejection
  - upside = Support absorption
- Trap type text is neutral, not direction-colored.
- Affected level guard:
  - downside must not resolve to an invalid level away from resistance; it falls back to displayed resistance
  - upside must not resolve to an invalid level away from support; it falls back to displayed support

  - if old S/R is missing, trace payload first before treating it as a styling issue

Web field mapping

SPC text correctness guards
- Breached states must never render as near-edge text.
- When spot > resistance:
  - center text must read above-resistance context

- Primary structural row must contain only:
  - S value or R value
- Shift/new indicators must use badge rendering (for example NEW), not inline token concatenation.
- Invalid pattern to reject:
  - "S newS 22,800"

SPC footer checks
- Side columns should render:
  - breakout probabilities above side targets
  - below-S target on support side
  - above-R target on resistance side
- Expected range remains centered.

Header chip cleanup

- Header should stay action/reason/bias focused.
